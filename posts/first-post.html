开源之路：个人技术博客的搭建与思考

2024-01-01✎博客建设

  • 博客
  • GitHub Pages
  • 开源分享

欢迎来到我的个人技术博客。这是一个记录我在技术探索路上的平台，也是我开源分享理念的体现。今天想和大家分享一下建立这个博客的初衷，以及我为什么决定把站点做成 Markdown 驱动的静态网站。

建站的初衷

作为一名开发者，我一直相信“分享即成长”。

  • 记录技术成长，把分散的学习经验系统化。
  • 分享开源项目，把踩过的坑和走通的路径说清楚。
  • 传播技术知识，帮助其他开发者解决实际问题。
  • 建立个人品牌，在技术社区中留下稳定输出。

为什么选择静态博客

对于个人博客，静态网站比传统 CMS 更适合长期维护。

  • 加载速度快，不依赖数据库查询。
  • 维护成本低，没有服务端运行和升级负担。
  • 安全性高，纯静态文件暴露面更小。
  • 版本可追踪，所有内容都可以直接放进 Git 仓库。

技术选型

这一版博客选择了最直接的一条路：HTML + CSS + 少量构建脚本。

GitHub Pages

GitHub Pages 很适合个人博客：

  • 部署简单，推送代码即可上线。
  • 原生支持静态资源托管。
  • 和仓库工作流天然整合。

Markdown 作为内容源

相比直接在 HTML 里写正文，Markdown 更适合写作：

  • 文章内容和页面结构分离。
  • 更容易维护长文。
  • 可以批量生成文章页、首页摘要和博客列表。
  • 后续要接入搜索、RSS 或标签页也更容易。

保留设计自由度

静态站点并不意味着样式受限。页面外观仍然由模板和 CSS 控制，内容则来自 Markdown。

/* 铅笔手绘风：虚线边框 + 交叉排线阴影 + 纸张底 */
        .sketch-box {
          background-color: var(--c-paper);
          border: 2px dashed var(--c-pencil);
          box-shadow: 2px 2px 0 0 var(--sh-md);
        }

        .post-body blockquote {
          padding: 1rem 1.25rem;
          border: 2px dashed var(--c-pencil);
          color: var(--c-pencil-2);
        }

内容规划

我希望这个博客长期覆盖几类内容：

  • AI 应用开发，尤其是 RAG 和工具链实践。
  • Web 开发，从前端到部署的完整经验。
  • 开源项目复盘，关注架构、取舍和维护。
  • 个人学习记录，把过程写清楚而不是只给结论。

持续迭代

博客建设不是一次性工作，而是持续优化的过程。

用户体验

  • 响应式布局，保证移动端阅读体验。
  • 更稳的排版和留白，降低长文阅读疲劳。
  • 首页和列表页自动从 Markdown 生成，减少手工同步错误。

内容质量

  • 尽量给出完整上下文，而不是只贴代码片段。
  • 保留关键设计取舍，方便后续复盘。
  • 让文章既能被读，也能被继续维护。

开源理念

这个博客本身也是我对开源理念的一次实践。

代码开源，知识共享。写出来不仅是记录，也是对社区的回馈。

我希望它能持续承担几件事：

  • 分享实际项目中的技术挑战和解决方案。
  • 公开整理有价值的工具和脚本。
  • 参与技术社区讨论，形成正向反馈。

未来规划

后续我会继续补充这些方向：

  • AI 应用开发系列：从 RAG 到 LLM 工作流。
  • 现代 Web 开发系列：从页面到构建部署。
  • 开源项目分析系列：从需求到架构演化。
